# Режим Codex

## Включение

- Режим включает пользователь: `/codex` или прямой просьбой («используй Codex»,
  «подключи Codex»). С этого момента и до конца разговора Claude может подключать
  агентов Codex по правилам ниже. «Без Codex», «выключи Codex» — режим выключен.
- Без включения Codex не используется: всё делает Claude сам. Читать треды Codex по
  просьбе пользователя можно всегда — это лимиты не тратит.
- При включении один раз проверь мост: `codex-bridge mode` (`shared` или `gui` — оба
  рабочие).

## Роли

- **Глубокая работа** — исследования, ревью, анализ, гипотезы, литература,
  архитектура, научные тексты — Claude делает сам и целиком. По своему усмотрению
  подключает Codex через `codex-bridge consult`: отдать часть задачи (подвопрос,
  исчерпывающий поиск, тяжёлый анализ данных, проверку кодом) или продублировать её
  ради независимого мнения и критики. Решения, суммаризация и итог — только Claude.
- **Исполнение** — код, баги, эксперименты, окружения, разбор кодовой базы ради
  изменений — Codex через `codex-bridge start`; Claude ставит задачу и проверяет.

## Выбор модели: по умолчанию Terra · medium

Лимиты Codex конечны, а уровень завышали: Sol high и ultra ставили даже там, где
хватило бы Terra medium. Поэтому лестница начинается снизу.

| Уровень | Когда |
|---|---|
| `terra` · `medium` — **по умолчанию** (и умолчание моста) | большинство поручений: найти и собрать источники или данные; выжимка статьи или треда; вытащить цифры из логов; свести таблицу; прогнать скрипт или эксперимент по готовой инструкции; написать скрипт по ясной спецификации; фикс с понятной причиной; проверить конкретное утверждение по источнику; переформатировать, задокументировать |
| `terra` · `high` / `xhigh` | то же, но много шагов, большой объём или легко ошибиться |
| `sol` · `medium` / `high` | нужна самостоятельная мысль, которой Terra не хватит: баг с неясной причиной, проектирование нетривиального модуля, разбор незнакомой большой кодовой базы, независимое экспертное мнение, критика аргументации |
| `sol` · `xhigh` | трудное: многошаговое рассуждение, спорный научный вопрос, глубокий литобзор с синтезом |
| `sol` · `max` / `ultra` | исключение: исключительно трудное или уже провалившееся уровнем ниже; мост требует `--why "<почему ниже не справится>"` |
| `astra` | только с разрешения пользователя: спроси одним вопросом и предложи уровень — «Здесь нужна Astra на `<effort>`, потому что … Разрешаешь или Sol на `<effort>`?»; затем `--astra-approved --why "..."` |

- Прежде чем поднять уровень выше `terra · medium`, назови себе одной фразой, почему
  ниже не справится. Не можешь — оставь ниже.
- Повышай по одной ступени (сначала effort, потом модель) после слабого результата, а
  не заранее.
- В пачке параллельных задач у каждой свой уровень — по её сложности.
- Уровни: `medium` (`med`), `high` (`hard`), `xhigh` (`extra`), `max`, `ultra`.
- Модель и effort, названные пользователем, приоритетны.

## Глубокая работа с Codex

- **Часть задачи** — `consult --kind research` (полный доступ, может запускать код).
- **Независимое мнение** по ключевому или спорному вопросу — `consult --kind opinion`,
  при необходимости `--n 2`. В бриф — вопрос, материалы, пути к данным, ограничения,
  **но не свои выводы**. Свою позицию формируй до чтения ответов.
- **Критика черновика** важного результата — `consult --kind critique`.
- Ожидание — в фоне (`codex-bridge wait <ids>` через Bash с `run_in_background: true`);
  Claude тем временем продолжает свою работу над вопросом.
- Результаты Codex — материал: совпадения укрепляют вывод, расхождения проверь по
  источникам сам (не голосованием), неподкреплённое отбрось, реши и обоснуй.

```bash
codex-bridge consult --kind research --title "Собрать статьи по X за 2024–2026" \
  --cwd ~/projects/x --prompt-file /path/to/task.md                     # terra · medium
codex-bridge consult --kind opinion --model sol --effort high \
  --title "Почему модель недолетает до цели" --prompt-file /path/to/question.md
codex-bridge consult --kind critique --model sol --effort medium \
  --title "Черновик отчёта" --prompt-file draft.md
```

`consult` сам оборачивает бриф в формат эксперта (позиция, обоснование, источники,
альтернативы, уверенность, что проверить); `--n` — число независимых тредов.

## Исполнение

Мелочь делай сам. Бриф исполнителю (Codex не видит наш разговор):

```
Цель: что должно получиться и зачем (1–3 предложения).
Контекст: что известно и решено; файлы, ветки, эксперименты, документы.
Что сделать: шаги или направление; что можно менять, что нельзя.
Ограничения: окружение, ресурсы, сроки, без каких действий (push, удаление данных, траты денег).
Критерии готовности: как проверить (команды, тесты, метрики).
Отчёт: что сделано, изменённые файлы, как проверено (команды и вывод), что не получилось, вопросы.
```

Приёмка: отчёт Codex — заявление, а не доказательство. Смотри `codex-bridge read <t>
--last 1 --items` и проверяй ключевое сам (`git diff --stat`, тесты, артефакты,
цифры). Уточнения — в тот же тред через `send`. Параллельные писатели в один
репозиторий не трогают одни и те же файлы (разведи зоны или дай каждому свой
`git worktree` в `--cwd`).

## `codex-bridge`

```bash
codex-bridge start --title "..." --cwd <папка> [--model terra --effort medium] --prompt-file <файл>
codex-bridge consult --kind opinion|critique|research --title "..." [--model ... --effort ...] [--n 2] --prompt-file <файл>
codex-bridge send <thread> --prompt-file <файл>    # уточнение в тот же тред
codex-bridge wait <t1> <t2> ... [--timeout 14400]  # 0 — ок, 2 — failed/interrupted, 3 — таймаут
codex-bridge read <thread> [--last 1] [--items]
codex-bridge status | running | list --search "..." | links | mode
```

Промпты пиши в файлы в scratchpad. Мост сам добавляет заголовок `[Claude → Codex]` и
ссылку на чат Claude (Codex может прочитать контекст: `codex-bridge claude-read <id>`).
Не копируй в бриф длинные куски разговора — давай выжимку.

## Что видит пользователь и что нельзя ломать

- Каждая задача — тред в Codex с твоим названием. Сообщай, что запущено: название ·
  модель · effort · ссылка `codex://threads/<id>`.
- `codex-bridge mode`: **shared** (основной у пользователя) — треды сами появляются в
  сайдбаре, задачи идут и при закрытом приложении; **gui** — новый тред один раз
  открывается в приложении в фоне.
- В shared у агентов Codex нет инструментов приложения `codex_app`; общение агентов
  идёт через встроенные `collaboration.*` и `codex-bridge`, библиотеки для документов —
  через MCP `codex_runtime`.
- Никогда не перезагружай MCP и не перезапускай общий сервер или Codex, пока
  `codex-bridge running` не пуст: это обрывает идущие ходы других чатов. Для MCP —
  `codex-bridge reload-mcp` (сам откажется).
- Ходы исполняет только Codex-сервер; не запускай их собственным `codex app-server`.

## Отчёт и память

- Пользователю: свой вывод с доказательствами; что дали треды Codex; что поручено
  исполнителям и что проверено; ссылки на треды.
- Если работа идёт по теме из Research Atlas — после значимого результата обнови
  страницу состояния темы (`memory_save`), треды Codex укажи в журнале или в отчёте.
