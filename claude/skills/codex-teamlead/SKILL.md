# Codex — субагенты Claude

Агенты Codex — субагенты Claude, только сильнее и долгоживущее. Claude решает, что им
отдать, проверяет результат и решает сам.

| Работа | Кто делает | Codex — когда и как |
|---|---|---|
| **глубокая**: исследование, ревью, анализ, гипотезы, литература, архитектура, научные тексты | Claude сам и целиком | по усмотрению Claude: часть задачи или дубль ради независимого мнения и критики — `codex-bridge consult`, по умолчанию `astra` · `ultra` (разрешено заранее) |
| **исполнение**: код, баги, эксперименты, окружения, разбор кодовой базы ради изменений | Codex | `codex-bridge start`: `terra` (рутина) / `sol` (сложное); `astra` — только с согласия пользователя |

## Глубокая работа

Claude делает её сам: формулирует вопрос, ищет в интернете, читает первоисточники,
код и данные, рассуждает и пишет. Codex подключается, когда это на пользу результату:

- **Отдать часть задачи** — подвопрос, который удобно вести отдельно; исчерпывающий
  поиск литературы; тяжёлый анализ данных; проверка гипотезы кодом или экспериментом:
  `consult --kind research` (полный доступ, может запускать код).
- **Продублировать ради независимого мнения** — ключевой или спорный вопрос, от
  которого зависит решение: `consult --kind opinion`, при необходимости `--n 2–3`. В
  бриф — вопрос, материалы, пути к данным, ограничения, **но не свои выводы** — иначе
  мнение перестанет быть независимым. Свою позицию формируй до чтения ответов.
- **Критика черновика** — для важных результатов (отчёт, статья, решение,
  архитектура): `consult --kind critique`.

Пока Codex работает, ожидание — в фоне (`codex-bridge wait <ids>` через Bash с
`run_in_background: true`), а Claude продолжает свою работу над вопросом.

**Решения, суммаризация и итог — только за Claude.** Результаты Codex — материал:
сверь их со своими, совпадения укрепляют вывод, расхождения проверь по источникам сам
(не голосованием), неподкреплённое отбрось, реши и обоснуй. Где полезно — укажи, в чём
Codex согласился или разошёлся и почему решено так.

**Нельзя:** перекладывать на Codex собственное суждение и решения; выдавать ответы
Codex за проверенные выводы; давать в бриф независимого мнения свой вывод «на
проверку» (для проверки вывода есть `critique`).

```bash
# второе мнение, два независимых треда Astra ultra, только чтение
codex-bridge consult --kind opinion --n 2 --title "Почему модель недолетает до цели" \
  --cwd ~/projects/x --prompt-file /path/to/question.md
# параллельный исследовательский трек (полный доступ: может запускать код)
codex-bridge consult --kind research --title "Литература по методам X за 2024–2026" \
  --cwd ~/projects/x --prompt-file /path/to/track.md
# критика черновика
codex-bridge consult --kind critique --title "Черновик отчёта по L1" --prompt-file draft.md
```

`consult` сам оборачивает бриф в формат эксперта (позиция, обоснование, источники,
альтернативы, уверенность, что проверить). Можно поменять `--model` и `--effort`;
`--n` — число независимых тредов.

## Исполнение: делегирование

Пороги: если по коду нужно больше ~5 tool-вызовов, много читать или долго ждать —
отдавай. Мелочь делай сам. Если пользователь сказал «сделай сам», делай сам.

| Задача | Модель | effort |
|---|---|---|
| рутина: переименовать, собрать файл, запустить скрипт, мелкий фикс по точной инструкции | `terra` (gpt-6.1-terra) | `medium`; `xhigh` — нужна аккуратность; `ultra` — редко |
| обычная сложная: фича, неочевидный баг, эксперимент, разбор кода, инфраструктура | `sol` (gpt-6.1-sol) | `xhigh` по умолчанию; `max` — трудное; `ultra` — самое трудное |
| исполнение, где Sol на `ultra` дважды не справился | `astra` | только после явного «да» пользователя: «Здесь взял бы Astra, потому что … Разрешаешь или Sol?» |

Модель и effort, названные пользователем, приоритетны. Мост не запустит Astra через
`start` без `--astra-approved`; `consult` ставит его сам — для консилиума Astra
разрешена заранее.

Бриф исполнителю (Codex не видит наш разговор, бриф самодостаточный, на русском):

```
Цель: что должно получиться и зачем (1–3 предложения).
Контекст: что известно и решено; файлы, ветки, эксперименты, документы.
Что сделать: шаги или направление; что можно менять, что нельзя.
Ограничения: окружение, ресурсы, сроки, без каких действий (push, удаление данных, траты денег).
Критерии готовности: как проверить (команды, тесты, метрики).
Отчёт: что сделано, изменённые файлы, как проверено (команды и вывод), что не получилось, вопросы.
```

Приёмка: отчёт Codex — заявление, а не доказательство. Смотри `codex-bridge read <t>
--last 1 --items` (команды и правки), проверяй ключевое сам (`git diff --stat`, тесты,
артефакты, цифры). Уточнения — в тот же тред через `send`.

## `codex-bridge`

```bash
codex-bridge start --title "..." --cwd <папка> --model sol --effort xhigh --prompt-file <файл>
codex-bridge consult --kind opinion|critique|research --title "..." [--n 2] --prompt-file <файл>
codex-bridge send <thread> --prompt-file <файл>    # уточнение в тот же тред
codex-bridge wait <t1> <t2> ... [--timeout 14400]  # 0 — ок, 2 — failed/interrupted, 3 — таймаут
codex-bridge read <thread> [--last 1] [--items]
codex-bridge status | running | list --search "..." | links | mode
```

Промпты пиши в файлы в scratchpad. Мост сам добавляет заголовок `[Claude → Codex]` и
ссылку на чат Claude; Codex может прочитать контекст: `codex-bridge claude-read <id>`.
Не копируй в бриф длинные куски разговора — давай выжимку.

Параллель смело и в нужном количестве. Писатели в один репозиторий не трогают одни
и те же файлы: разведи зоны или дай каждому свой `git worktree` (путь — в `--cwd`).

## Что видит пользователь и что нельзя ломать

- Каждая задача — тред в Codex с твоим названием; давай ссылки `codex://threads/<id>`
  и список запущенного: название · модель · effort.
- `codex-bridge mode`: **shared** (основной у пользователя) — треды сами появляются в
  сайдбаре, окно не переключается, задачи идут и при закрытом приложении; **gui** —
  новый тред один раз открывается в приложении в фоне.
- В shared агенты Codex общаются сами: субагенты (`collaboration.*`), отдельные треды
  и переписка через `codex-bridge` (`[Codex → Codex]`), встроенные библиотеки для
  документов через MCP `codex_runtime`. Нет автоматизаций, инструментов worktree,
  организации сайдбара и панелей приложения.
- Никогда не перезагружай MCP и не перезапускай общий сервер или Codex, пока
  `codex-bridge running` не пуст: это обрывает идущие ходы, в том числе задачи других
  чатов. Для MCP — `codex-bridge reload-mcp` (сам откажется).
- Исполняет задачи только Codex-сервер; не запускай ходы собственным `codex app-server`.
  `/opt/homebrew/bin/codex` устаревший — мост использует CLI из Codex.app.

## Отчёт и память

- Пользователю: собственный вывод с доказательствами; что дал консилиум; что поручено
  исполнителям и что проверено; ссылки на треды.
- Если активен Research Atlas — материальные результаты сохраняй checkpoint'ом,
  треды Codex — среди источников.
