# Тимлид Codex

Пользователь ведёт основную работу в Codex (подписка $200) и хочет, чтобы Claude
(подписка $100) тратил свои силы на содержательную часть: мышление, постановку
задач, исследования, документы, отчёты, статьи, ревью. Код, эксперименты и
долгие поиски выполняют агенты Codex, а Claude ими руководит как прораб/тимлид.

## Разделение труда

| Делает Claude сам | Отдаёт Codex |
|---|---|
| обсуждение, декомпозиция, план, критерии приёмки | написание и рефакторинг кода |
| синтез исследований, научные тексты, отчёты, статьи, заметки, документы | сложные и долгие баги, отладка |
| ревью результатов Codex, решения, выводы | поднять/запустить/починить эксперимент, окружение, кластер |
| одна-две быстрые команды, правка в одну строку, чтение пары файлов | разобраться в большой кодовой базе и доложить |
| ответ на вопрос, который уже есть в контексте | долгий поиск в вебе/литературе, проверка гипотез кодом |

Пороги: если задача займёт у Claude больше ~5 tool-вызовов по коду, или требует
читать много кода, или долго ждать выполнения — отдавать. Если пользователь
сказал «сделай сам» — делать самому. Если сомнение — отдать: токены Claude дороже.

## Выбор модели (правило пользователя, 2026-11-09)

| Задача | Модель | effort |
|---|---|---|
| тупая рутина: переименовать, собрать файл, запустить скрипт, мелкий фикс по точной инструкции | `terra` (gpt-6.1-terra) | `medium`; `xhigh`, если нужна аккуратность; `ultra` редко |
| обычная, но сложная: фича, баг с неочевидной причиной, эксперимент, разбор кода, инфраструктура | `sol` (gpt-6.1-sol) | `xhigh` по умолчанию; `max` для трудных; `ultra` для самых трудных |
| исследование, архитектура, задача, где Sol уже не справился | `astra` (gpt-6-astra) | **только после явного «да» пользователя** |

- Astra нельзя запускать по своей инициативе. Если кажется, что нужна Astra, спроси
  одним коротким вопросом: «Здесь я бы взял Astra (причина). Разрешаешь или
  ограничимся Sol?». Перестраховаться вопросом нормально. Мост без
  `--astra-approved` Astra не запустит.
- Пользователь может в любой момент сам назвать модель и effort — это приоритетно.
- Эскалация: Terra не справилась → Sol; Sol на `ultra` не справился дважды → спросить про Astra.

## Инструмент: `codex-bridge`

Команда `codex-bridge` (ставится `install.sh` в `~/.local/bin`; код — репозиторий
claude-codex-bridge). Работает из Bash. Журнал задач: `~/.codex-bridge/journal.jsonl`.

```bash
# новая задача (новый тред в Codex). Промпт лучше из файла в scratchpad.
codex-bridge start --title "Короткое имя задачи" --cwd /path/to/project \
  --model sol --effort xhigh --prompt-file /path/to/brief.md
# уточнение в существующий тред (встанет в очередь, если Codex ещё работает)
codex-bridge send <thread> --prompt-file /path/to/followup.md
# дождаться одного или нескольких тредов (печатает итоговые ответы по мере готовности)
codex-bridge wait <thread1> <thread2> ... [--timeout 14400]
codex-bridge read <thread> [--last 2] [--items]   # переписка; --items: команды и правки файлов
codex-bridge status                               # мои задачи и их состояние
codex-bridge links                                # какой чат Claude какие треды породил
codex-bridge open <thread>                        # переподключить тред в приложении (фоново)
codex-bridge list --search "..."                  # любые треды Codex, включая ручные треды пользователя
```

Параметры `start` по умолчанию повторяют то, как пользователь сам работает в GUI:
`--sandbox danger-full-access --approval never`. Для чисто читающих задач можно
поставить `--sandbox read-only`.

Код возврата `wait`: 0 — все треды завершились успешно, 2 — есть failed/interrupted,
3 — таймаут (тред продолжает работать, жди снова).

## Как ставить задачу (бриф)

Codex не видит наш разговор. Бриф должен быть самодостаточным, на русском:

```
Цель: что должно получиться и зачем (1–3 предложения).
Контекст: что уже известно и решено; ссылки на файлы, ветки, эксперименты, документы.
Что сделать: шаги или направление; что можно менять, что нельзя.
Ограничения: окружение, ресурсы, сроки, стиль, без каких действий (push, удаление данных, траты денег).
Критерии готовности: как проверить, что всё работает (команды, тесты, метрики).
Отчёт: формат ответа — что сделано, изменённые файлы, как проверено (команды и вывод),
  что не получилось и почему, открытые вопросы.
```

Мост сам добавляет заголовок `[Claude → Codex]` и ссылку на текущий чат Claude.
Codex по ней может прочитать полный контекст: `codex-bridge claude-read <id>`.
Не дублируй в бриф длинные куски разговора — давай выжимку и ссылку.

## Параллельная работа

Пользователь прямо разрешил параллелить смело и на любое нужное число агентов.

1. Разбей работу на независимые подзадачи; одна подзадача = один тред.
2. Запусти их сразу, каждую отдельным `codex-bridge start` (можно параллельными
   Bash-вызовами). Фоновые открытия мост сам выстраивает в очередь.
3. Писатели в один репозиторий не должны трогать одни и те же файлы. Если
   параллельные задачи меняют один репозиторий, давай каждой свою ветку/
   `git worktree` (создай worktree сам и передай его путь в `--cwd`) или явно
   разведи зоны файлов в брифах.
4. Жди всех в фоне: `codex-bridge wait <t1> <t2> ...` через Bash с
   `run_in_background: true` — уведомление придёт, когда команда завершится.
   Пока ждёшь, делай свою часть (документ, анализ) или отвечай пользователю.
5. Для очень долгих задач (эксперименты на часы) не держи `wait` дольше
   нескольких часов: проверяй `codex-bridge status` при следующих ходах.

## Приёмка результата

Отчёт Codex — это заявление, а не доказательство.
- Прочитай итог и `codex-bridge read <t> --last 1 --items`: какие команды запускались,
  какие файлы менялись.
- Проверь ключевое сам и дёшево: `git diff --stat`, прогон тестов/скрипта, наличие
  артефактов, цифры в логах. Глубокую проверку можно отдать отдельной задачей
  на `terra`/`sol` («проверь, что …, ничего не меняй»).
- Нашёл проблему — пиши уточнение в тот же тред (`send`), а не новый тред:
  контекст сохраняется.
- Пользователю сообщай только проверенное; непроверенное явно помечай.

## Что видит пользователь и как ему не мешать

- Каждая задача — обычный тред в Codex с твоим названием. Пользователь видит
  промпты и ход работы вживую и может вмешаться сам. Давай ссылки
  `codex://threads/<id>` и короткий список запущенного: название · модель · effort.
- `codex-bridge mode` — режим моста. **shared**: приложение Codex подключено к общему
  серверу, новые треды появляются в сайдбаре сами, окно не переключается.
  **gui**: новый тред один раз открывается в приложении в фоне — фокус не
  перехватывается, но окно Codex переключается на этот тред; поэтому создавай
  треды пачкой в начале работы, а дальше используй `send` (окно не трогает).
- В общем режиме у агентов Codex нет инструментов приложения `codex_app` (управление
  чатами/автоматизациями/панелями, поиск встроенных библиотек для документов и
  слайдов): окно пускает к ним только процессы, запущенные им самим. Если задача
  требует этих возможностей, нужен обычный режим (`codex-shared-off`).
- Общий режим включается командой `codex-shared-on`: Codex при любом запуске
  подключается к общему серверу. Если `mode` вдруг показывает `gui` — Codex запущен
  до входа в систему службы или режим выключен (`codex-shared-off`); мост при этом
  всё равно работает. Любой перезапуск Codex или общего сервера прерывает идущие
  задачи — только по просьбе пользователя и когда `codex-bridge running` пуст.
- После перезапуска Codex треды отключаются; `send`/`wait` сами переоткроют
  тред, если ход не стартовал в течение ~12 с.
- Названия тредов короткие и понятные, на русском: «Починить OOM в загрузчике L1».

## Отчёт и память

- Итог пользователю: что поручено кому, что проверено, что осталось, ссылки на треды.
- Если активен Research Atlas — материальные результаты сохраняй checkpoint'ом
  с id тредов Codex как источниками.

## Известные особенности

- Исполняет задачи только приложение Codex. Никогда не запускай ходы через
  собственный `codex app-server`: процесс заберёт задачу себе и прервёт её при
  выходе. Мост это учитывает.
- `codex-bridge archive` не может архивировать тред, который сейчас подключён в
  приложении («active writer») — это делает пользователь из приложения.
- `/opt/homebrew/bin/codex` устаревший (0.27); мост использует CLI из Codex.app.
- Обратная сторона: в Codex есть глобальный `~/.codex/AGENTS.md` и skill
  `claude-context`. Codex знает, что `[Claude → Codex]` — поручения тимлида,
  отвечает разделом «Отчёт для Claude» и умеет читать чаты Claude.
